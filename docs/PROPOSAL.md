## 1. 项目背景：我们到底在解决什么

### 1.1 三个高频、低效率的真实场景

**场景一：绩点算不清，保研边缘反复横跳。**

每学期出分后，同学最常问的三个问题是「我 GPA 到底多少」「按我们学校算法是多少」「我再考高一点有用吗」。现实是：

- 教务系统一般只给「学分加权平均分」或某个单一口径的绩点，不给算法说明；
- 网上现成的 GPA 计算器大多是留学向的 4.0 制，和国内高校的 5.0 制、北大算法、浙大算法对不上；
- 想知道「我把哪门课提上去最划算」，只能自己在 Excel 里反复改数试。

**场景二：选课凭感觉，撞课靠运气。**

选课系统只会提示「时间冲突」，但它不会告诉你：两门课一节是单周、一节是双周，实际只撞 4 周；也不会告诉你这学期到底哪几天能空出来做实习、社团、考研复习。

**场景三：论文交稿前一晚，全组在手工改参考文献。**

同一篇论文投不同期刊、交不同课程作业，要在 GB/T 7714、APA、MLA、BibTeX 之间来回切。现成工具要么只做单一格式，要么要求注册登录，要么把文献上传到服务器——没人愿意把自己未发表的论文题录传上去。

### 1.2 现有方案为什么不够好

| 现有方案 | 能解决 | 差在哪 |
| --- | --- | --- |
| 留学向 GPA 计算器 | 4.0 制换算 | 算法单一，不含国内高校口径；不支持粘贴教务成绩；没有提分建议 |
| Excel / 手算 | 什么都能算 | 每次都要重建公式，同学之间无法复用，容易算错 |
| 教务系统 | 官方数据 | 只给一种口径，不给对比，也不给「如果我考高一点」的推演 |
| Zotero / 文献管理器 | 格式化参考文献 | 要装客户端、要学 CSL，对只改一条参考文献的同学太重 |
| 在线格式转换小站 | 单条转换 | 多为闭源、有广告、要上传数据，格式细节（GB/T 7714 的文献类型标识）经常错 |

**结论**：这三件事的共同特点是——**高频、碎片、对隐私敏感、需要贴合本校/本院口径**。它们不需要一个 App，只需要一个打开就能用、用完就走、算得准的网页。

## 2. 为什么选 IT-Tools 作为底座

### 2.1 技术层面：加一个工具的边际成本极低

- **架构约定是「一个工具 = 一个组件」**：`src/tools/<工具名>/` 下放 `index.ts`（元信息）+ `.vue`（视图）+ `.service.ts`（纯逻辑），再在 `src/tools/index.ts` 里注册到某个分类即可。我们新增三个工具，几乎没有改动上游任何既有代码。
- **技术栈成熟**：Vue 3 + TypeScript + Naive UI + Vite，自带 i18n（vue-i18n）、PWA（vite-plugin-pwa）、主题切换、搜索、收藏、路由，这些"外壳能力"直接复用，我们只写业务逻辑。
- **逻辑与视图分离**：算法放在 `.service.ts` 里是纯函数，方便写单元测试，也方便同学 review 算法对不对——这点对绩点这种"算错了会出事"的功能尤其重要。
- **天然纯前端**：没有后端，成绩和课表不出浏览器，隐私风险最低。

### 2.2 生态层面：站在有用户的肩膀上

it-tools 月活很高、社区活跃、持续维护。这意味着我们 fork 出来的版本可以直接获得：成熟的交互细节（快捷键、收藏、深色模式）、已经被验证过的 UI 组件库、以及上游持续修复的 bug。我们只需要专注"校园场景"这一层。

### 2.3 许可层面：GPL-3.0 对校园项目不是负担，是优势

GPL-3.0 有传染性，但换一个角度看：**它保证了任何人拿走我们的改进，都必须同样开源回来**。对校园公益工具来说，这正是我们希望的——同学之间互相改进、成果不会被某个商业产品悄悄吃掉。详细的合规承诺见第 5 章。

### 2.4 风险与应对

| 风险 | 应对 |
| --- | --- |
| 上游大版本重构，合并冲突 | 我们的改动集中在 `src/tools/` 三个新目录 + 少量配置，冲突面很小；保持 upstream remote，定期 rebase |
| 算法口径被质疑 | 每个算法在界面上直接写出公式/分档表，并提供「自定义分档表」，让同学按本校教务处的口径自行对齐；源码公开可 review |
| 同学不信任网页工具 | 强调纯前端、可离线、开放源码；提供自托管 Docker 部署说明 |

## 3. 产品方案

### 3.1 定位与用户画像

- **核心用户**：大二至大四本科生（绩点、选课、论文三件事最集中的人群）
- **次级用户**：研究生（参考文献格式转换）、学生会/社团骨干（公文与活动排期，后续迭代）
- **使用时机**：出分周、选课周、论文交稿周 —— 一年三个明确的流量高峰

### 3.2 功能地图

```
校园工具箱
├── 校园学习（新增分类）
│   ├── 绩点 / 加权平均分换算        ← 新增
│   ├── 课表冲突检测与空闲时段        ← 新增
│   └── 参考文献格式转换             ← 新增
└── 原 it-tools 全部工具（加密 / 转换 / Web / 开发 / 网络 / 数学 / 文本 …）
    └── 对计算机、电子、软件类专业同学仍然高频使用
```

### 3.3 新增工具一：绩点 / 加权平均分换算（`/gpa-calculator`）

**解决什么**：一次录入，同时得到 5 种口径的结果 + 提分建议。

**功能设计**

1. **教务系统直接粘贴导入**：支持 CSV / TSV / 空格分隔，自动识别「课程名称 / 学分 / 成绩」列；成绩列里的「优 / 良 / 中 / 及格 / A-」会自动换算成百分制中位数。
2. **五种算法随时切换**：标准 4.0、北大 4.0、浙大 4.0、浙大 5.0（绩点 = 分数÷10 − 5）、WES 认证 4.0；界面上直接展示每种算法的公式/分档表，可自查。
3. **自定义分档表**：按 `90:4.0, 85:3.7, 60:1.0` 的格式自己填，对齐本校教务处的特殊口径。
4. **同时给出三种分数**：GPA、学分加权平均分、算术平均分（保研看加权、奖学金看算术，二者经常不是同一个排名）。
5. **提分性价比榜（差异点）**：设定一个目标分（默认 90），工具会逐门课模拟"这门课考到目标分后 GPA 是多少"，按涨幅排序。它直接回答了「下学期我该重点冲哪门课」。
6. **目标 GPA 反推（差异点）**：输入想达到的 GPA，算出还差多少「绩点×学分」，并按提分效率从高到低给出建议课程清单；如果靠提分补不上，会明确提示"更现实的是多修几门高分选修课摊薄"。
7. **细节**：可单独勾选/排除某门课（体育课、重修前旧成绩）、不及格课程提醒、一键复制成绩单 CSV、数据自动存 localStorage。

**为什么比同类网页工具更好用**

| 对比项 | 常见 GPA 网页工具 | 我们的工具 |
| --- | --- | --- |
| 录入方式 | 一门一门手填 | 教务系统整表粘贴自动解析 |
| 算法 | 单一 4.0 制 | 5 种内置 + 自定义分档表，并排对比 |
| 结果 | 只给 GPA | GPA + 加权平均分 + 算术平均分 |
| 决策支持 | 无 | 提分性价比榜 + 目标 GPA 反推 |
| 数据 | 刷新即丢 / 需上传 | localStorage 本地保存，零上传 |

### 3.4 新增工具二：课表冲突检测与空闲时段（`/schedule-conflict`）

**解决什么**：把"选课系统说冲突"变成"哪几周、哪几节冲突，以及我什么时候有空"。

**功能设计**

1. **三维冲突检测**：`星期 × 节次 × 周次` 三者同时求交集。支持全周 / 单周 / 双周 / 自定义周次（`1-8,10-16`）。
2. **不误判**：单双周错开的课不会被判成冲突——这是教务系统做不到的。
3. **冲突明细**：列出「A 课 × B 课 / 周几 / 第几节 / 第几周（共 N 周）」。
4. **周课表网格可视化**：12 节 × 7 天，冲突格标红，单双周课程在格子里标注。
5. **空闲时段计算**：按天列出空档节次（合并成"第 3-4 节"这样的区间），并给出"整天没课""可以睡懒觉（前两节没课）"两个学生真正关心的视角。
6. **批量粘贴导入**：`高等数学 周一 1-2节 1-16周 教三301` 这样的文本，一行一门课自动解析。

### 3.5 新增工具三：参考文献格式转换（`/reference-formatter`）

**解决什么**：填一次字段，五种格式同时出；也能把已有文献粘回来反向解析、批量换格式。

**功能设计**

1. **八种文献类型**：期刊、专著、学位论文、会议论文、报纸、报告、标准、电子资源。
2. **一次输入，五种输出**：GB/T 7714-2015（含 `[J] [M] [D] [C] [N] [R] [S] [EB/OL]` 类型标识）、APA 7th、MLA 9th、IEEE、BibTeX，每条都带一键复制。
3. **作者姓名自动处理**：中英文姓名分别处理（中文 姓+名 全写；英文 `Smith, J.` / `J. Smith` / `Smith J` 都能识别），超过 3 位作者自动补「等 / et al.」。
4. **反向解析**：粘贴一条 GB/T 7714 或 BibTeX，自动拆回字段填进表单，改完再输出。
5. **批量转换**：BibTeX 整段或一行一条的 GB/T 7714，一键转到目标格式。
6. **零上传**：全程本地计算，未发表的论文题录不会离开本机。

### 3.6 体验、本地化与离线

- **中文界面**：默认语言改为简体中文，新增三个工具的中文名称与描述，新增「校园学习」分类词条，分类名支持 i18n 翻译（保留英文回退）。
- **离线可用**：强化 PWA 配置，预缓存全部静态资源并配置 `navigateFallback`；断网时站点仍可打开使用，导航栏会以「离线图标 + 提示」明确告知当前状态。宿舍网、图书馆 Wi-Fi 不稳定的场景下依然可用。
- **隐私**：三个工具没有任何网络请求，成绩、课表、文献题录只保存在浏览器 `localStorage`，并提供一键清空。

## 4. 技术实现

### 4.1 架构

沿用上游架构，未引入新的后端或第三方服务：

```
src/
├─ tools/
│  ├─ index.ts                    # 注册新分类 Campus 与三个工具
│  ├─ gpa-calculator/             # 新增
│  │  ├─ index.ts                 # 工具元信息（名称/路径/关键词/图标/创建时间）
│  │  ├─ gpa-calculator.service.ts# 纯函数：算法表、GPA 计算、提分模拟、表格解析
│  │  └─ gpa-calculator.vue       # 视图
│  ├─ schedule-conflict/          # 新增（周次展开、交集检测、空闲时段、课表网格）
│  └─ reference-formatter/        # 新增（五种格式渲染、作者解析、反向解析、批量）
├─ components/CollapsibleToolMenu.vue  # 分类名 i18n
├─ components/NavbarButtons.vue        # 离线状态提示
├─ plugins/i18n.plugin.ts              # 默认语言 zh，回退 en
└─ ...
vite.config.ts                    # PWA 预缓存 + 中文 manifest
locales/{zh,en}.yml               # 新工具与分类词条
```

### 4.2 关键实现要点

- **绩点算法表**：以 `{ min, point }` 分档表 + 可选连续公式两种方式表达，新增算法只需往 `GRADE_SCALES` 里加一项，不改计算逻辑。
- **成绩解析**：`parseScoreInput` 同时支持数字与等级制（`优/良/中/及格/A-/B+`），等级映射为百分制中位数，并在界面上仍显示原始输入，避免"被换算"造成误解。
- **课表周次**：周次统一展开成数组后用集合求交集，单双周与自定义周次共用一套逻辑，避免分支漏判。
- **参考文献**：作者解析拆成 `family / given / isChinese`，各格式用自己的连接函数（GB/T 7714 的 `姓大写 + 名首字母`、APA 的 `Family, I.`、IEEE 的 `I. Family`），互相独立、便于单独修正。
- **持久化**：统一用 `useStorage`，刷新不丢数据；不引入任何后端。

## 5. 开源合规：我们对 GPL-3.0 的理解与承诺

### 5.1 我们的理解

it-tools 采用 **GNU GPL v3**。GPL 是"著佐权（copyleft）"许可，具有**传染性**：

- 我们 fork 并修改了它的代码，只要我们**对外分发**（包括把构建后的站点公开部署给同学访问，这在 GPL 语境下构成"提供可执行文件/衍生作品"），就必须**以同样的 GPL-3.0 许可公开全部修改后的源代码**；
- 我们的新增文件属于"衍生作品"，同样受 GPL-3.0 约束；
- 我们不能把本项目整体或部分以闭源形式打包、上架、授权给第三方，也不能通过技术手段（如混淆后只提供 SaaS 而不提供源码）规避开源义务。

**这不是障碍，而是我们选择它的原因**：校园工具的价值在于持续被同学改进，GPL 保证了这份改进永远回流到公共池。

### 5.2 我们的五条具体承诺

1. 仓库保持 **GPL-3.0**，`LICENSE` 文件不做任何修改；
2. 修改过的文件在文件头部注明改动内容与日期，保留上游作者署名；
3. 公开部署时，在站点显著位置（关于页 + 页脚）提供指向本仓库的源码链接，并注明基于 CorentinTh/it-tools（GPL-3.0）二次开发；
4. 新增的三个工具同样以 GPL-3.0 发布，任何二次使用者享有同等权利、承担同等义务；
5. 若未来与学校/第三方合作定制，涉及本项目的改动一律回到本仓库开源，不做闭源分支。

### 5.3 对用户侧的说明

在关于页面用通俗语言写明：「本站所有代码开源（GPL-3.0），你可以自由使用、修改和分享，但修改后的版本也必须同样开源。」让同学知道自己拥有什么权利。

## 6. 落地推广：怎么让同学真正用起来

不做"开发完就发群里然后没人点"的一次性推广，而是绑定三个**每年必然发生**的时间点。

### 阶段 0：种子验证（第 1-2 周，20 人）

- 找 20 位不同专业的同学，用他们自己上一学期的真实成绩单试用，重点验证：算法口径对不对、教务系统粘贴能不能解析、结果和他自己算的是否一致。
- 收集至少 10 条具体反馈，修掉 Top 3 问题。
- 产出：一张"算法对照说明图"，解答「为什么我的 GPA 和教务系统不一样」。

### 阶段 1：出分周首发（第 3-4 周）

- **渠道**：院/班群、年级群、社团群，配上"三步算出你的 GPA"截图教程。
- **物料**：A4 二维码海报（食堂门口、宿舍楼下、教学楼电梯口），二维码直接指向绩点工具。
- **钩子**：海报文案不写"工具箱"，写问题——「你的 GPA 到底是多少？5 种算法，10 秒算完」。

### 阶段 2：选课周 + 论文季（第 5-8 周）

- 选课周推课表冲突检测，文案：「别让两门课撞在第 6 周」。
- 论文季推参考文献转换，试点路径：先找 2-3 位毕业论文导师/课程助教，让他们在作业要求里附上使用链接。
- 与学生会宣传部、学业辅导类社团合作，做一次 15 分钟的线下分享（"毕业前你必须会用的三个小工具"）。

### 阶段 3：常态化与共建（持续）

- 在关于页放"提需求 / 报 bug"入口，所有需求公开在 GitHub Issues，同学可投票。
- 每学期出分周固定复盘一次数据，更新算法表与解析规则。
- 招募 2-3 位同学参与维护（一人负责算法校对、一人负责文案与推广、一人负责前端），把项目做成可持续的社团项目而非一次性作业。

### 关键设计：为什么同学会留下来

- **不注册、不登录、不装 App**：扫码即用是校园场景的最低门槛。
- **数据留在本地**：成绩单是敏感数据，不上传是最强的信任基础。
- **离线可用**：断网也能算，弱网环境体验一致。
- **有结果、有建议**：给的不只是一个数字，而是"下一步该冲哪门课"。

## 9. 双创大赛视角

- **创新性**：不是做一个新 App，而是"用开源项目的成熟底座 + 校园场景的深挖"做低成本高价值的微创新；差异点在于**决策支持**（提分性价比榜、目标 GPA 反推、周次级冲突检测），而不只是"能算"。
- **社会价值**：直接服务学业公平——很多同学因为不会算、算错口径，错过保研、奖学金、交换的申请窗口。工具免费、无广告、不采集数据。
- **可持续性**：纯静态站点，托管成本极低（可部署在学校服务器或免费静态托管）；维护成本集中在"每学期核对一次算法"。团队以社团形式传承，不依赖某一个人。
- **商业模式（非营利优先）**：不向学生收费。可选的自我造血方式：学校/学院信息化定制（定制本院算法与导入格式）、赞助与捐赠、面向新生的学业工具培训。任何定制改动按 GPL-3.0 回流开源。
